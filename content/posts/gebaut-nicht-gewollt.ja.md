私は、すべてを一つにまとめて自動化するプラットフォームをつくりました——寄贈された古い機器から、品質管理を経て、公開のショーウィンドウまで、さらに内部業務のすべてを含めて。Revamp-IT はこの道を一緒に歩まないことを決め、既存のシステムにとどまっています。Joomla のウェブサイト、別立ての Shopware ショップ、そして本当のインターフェースを持たない Perl 製の ERP である Kivitendo です。これは協会の決定です。私は自動化された道のほうが優れていると確信しており、**evig** としてそれを独自に進めていきます。

この記事はその正直な比較です。あとから蹴るのではなく、並べて示すものです——**何があったか**、**私が何をつくったか**、そして**どこへ向かうのか**。

## 何があったか：黙り込んだ三つのシステム

年月を経て、Revamp-IT では三つの分断された旧システムが育っていました。それぞれに独自の目的と独自のデータを持っていました。

- `revamp-it.ch` 上の **Joomla のウェブサイト** — 公開の顔でありながら、静的で他から切り離されていました。
- `shop.revamp-it.ch` 上の **Shopware ショップ** — 再生済み機器の販売、それ自体で一つの宇宙でした。
- **Kivitendo の ERP** — 会計と在庫。Perl で書かれ、閉ざされていて、使えるAPIがありませんでした。

この三つは互いに口をききませんでした。登録され、検査され、保管され、販売される機器は、どの工程でも手で打ち直さなければなりませんでした。データはコピーによって溝を越えて渡り歩き——手作業の転記がもたらすあらゆる誤りを伴っていました。そして Kivitendo には本当のインターフェースがないため、あらゆる自動化の試みは同じ壁にぶつかって終わります。存在しないAPIを探すか、そもそもデータを出し入れするためだけに苦労してブラウザをまねるかです。

修理そのものが問題だったことは一度もありません。その背後にある組織が問題だったのです。

## 私が何をつくったか：公開と内部を同時に担うプラットフォーム

三つの旧システムをガムテープで貼り合わせて保たせ続ける代わりに、私は一つのまとまったプラットフォームをつくりました。それは両方の世界をカバーします——コミュニティが見て回り、購入し、助けを求める**公開の側**と、機器を登録し、検査し、公開し、時間を記録し、業務を調整する**内部の側**です。両者は同じデータ基盤を共有します。機器は**一度だけ**登録され、そこから自動的にショーウィンドウまで渡っていきます。

![フィルター、CO₂ バー、出品を備えたマーケットプレイス](/blog/showcase-revampit-marketplace.png)
*マーケットプレイス：再生済み機器と個人の出品を一つのショーウィンドウに、フィルターと透明な CO₂ バーとともに。*

- **マーケットプレイス** — 再生済み機器と個人間のピアツーピア取引を一つの場所に。一つのカート、一つのチェックアウト、エスクロー機能付きの Payrexx による支払い。
- **IT ヘルプ** — 修理の必要を技術者とつなぐ双方向のネットワーク。一つの修理は、廃棄物から一台減ることを意味します。
- **サービス** — 「あなたのコンピューターを組み立てる」、Linux のインストールと相談、適正なリサイクル。
- **機器の受け入れ** — AI 支援による登録が写真と主要データを取り込み、カテゴリーとデータを提案します。検査が必要なカテゴリーは、チェックリストと四つの目の原則を用いた構造化された品質管理を通ります。数量向けには一括登録と CSV インポートがあります。
- **勤怠記録、チーム、そして Hirn** — 業務のための残高、レポート、承認フロー。誰が何に取り組んでいるかを示すチーム構造。そして「Hirn」、組織自身の知識にもとづいて答える RAG ベースの AI アシスタント。
- **CO₂ への影響** — すべての数値をその導出とともに開示（ADEME の係数を、Fraunhofer と ZHAW と照合）し、専用の透明性ページに掲載。主張ではなく、実証です。

![透明性ページ上の CO₂ 算定手法](/blog/showcase-revampit-co2.png)
*すべての CO₂ の数値は公開されたソースに結び付けられ、計算は公開されています——グリーンウォッシングではなく、検証可能です。*

## 直接の比較

| | 以前（Revamp-IT、旧システム） | 現在（プラットフォーム） |
|---|---|---|
| **システム** | 三つに分断（Joomla、Shopware、Kivitendo） | まとまった一つのアプリ |
| **データ入力** | どの工程でも手で打ち直し | 一度登録すれば自動で受け渡し |
| **ERP 連携** | Kivitendo（Perl）、本当のAPIなし | Kivvi と REST API 同期（`syncToKivvi`） |
| **販売と P2P** | 分断、あるいはそもそも存在せず | 一つのマーケットプレイス、一つのチェックアウト |
| **検索** | 横断的なものはなし | 在庫全体にわたる Meilisearch |
| **持続可能性** | 主張 | すべての数値に公開ソース |
| **言語** | 実質的に一つ | 8 |
| **内部（時間、チーム、知識）** | 散在／手作業 | プラットフォーム内に、AI アシスタントとともに |

個々の技術よりも重要なのは、その背後にある原則です——あらゆる情報について**唯一の真実の源**を持つこと。まさに三つの旧システムに欠けていたものです。

## 規模

「黙り込んだ三つのシステム」から、相当な奥行きを持つプラットフォームが生まれました（2026年7月時点）。

| 指標 | 値 |
|---|---|
| API エンドポイント | 300 以上 |
| ページ | 220 以上 |
| 管理モジュール | 33 |
| データベースのテーブル | 約 130 |
| 言語 | 8 |
| コミット | 2'300 以上 |

内側では、**Next.js 16** と **TypeScript**、**Drizzle** ORM を介した **PostgreSQL** 上のデータ（型はスキーマから直接導出）、**NextAuth v5** によるログイン、**Meilisearch** による検索、**Payrexx** による支払い、**Cloudflare R2** 上の画像。あらゆる自動化が挫折する Perl 製 ERP ではなく、意識して選ばれた現代的なスタックです。

## どこへ向かうのか

プラットフォームは目標ではなく、土台です。evig は循環経済からさらに一歩進みます——**すべての人にとっての知性へのアクセス**へと。これがロードマップです。

- **控えめなハードウェア上での手頃な AI。** 再生されたノートパソコンは、より環境にやさしい選択であるだけでなく、人工知能への最も安価な入り口です。私たちは、能力ある AI がセカンドライフの機器上でどう動くかを研究し、示します。
- **次の一歩としてのロボティクス。** 身体を持つ知性——人生から本当の労働を取り去り、時間を返してくれるロボット。ヒューマノイドは今日ほとんど新品では売られておらず、まだ使われてもいません。evig は、それらをきちんと提供する最初の場所でありたいと考えています。完全で、検査済みで、実際の目的のために裏付けられ——そして使いこなす知識とともに。
- **知性を手にする新しい方法。** 直接の購入に加えて：サブスクリプション型のクラウドファンディングと共同出資、共有されるサブスクリプションのプール（AI のランニングコストを一人で背負う代わりに分け合う）、仲介者を介さない直接の支援。
- **開かれた形で進める研究。** evig は売って修理するだけではありません——探究します：手頃な AI、開かれたロボティクス、修理、自分の道具に対する主権。そして見つけたことを公開します。循環する知識は、循環するハードウェアと同じ考えです。

これが「あったままで十分」と「行けるところまで行く」の違いです。私はこの道を歩みたいから土台をつくりました——速く、独自に、そしてチューリッヒを越えて。

## 結び

三つの旧システムが並んで動き、データが手で溝の向こうへ運ばれていた場所に、今日ではまとまった自動化されたプラットフォームが立っています。それは存在し、動いており、検証可能でした。Revamp-IT はよく知られた道を選びました——それは彼らの正当な権利であり、2003年以来続けてきた仕事は価値あるものであり続けます。私はもう一方を選びました：すべてを一つにまとめ、可能なかぎり自動化し、土台を知性の時代へと向けることを。

evig はさらに築いていきます。同じ根、より大きな目標。
